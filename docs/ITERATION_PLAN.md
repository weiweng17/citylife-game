## 范围与原则

- 基于 D:\打工人模拟器\citylife-game-github 的现有 Godot 4.7.2 源码和用户美术包开发，不另起原型，不推送远程。
- 采用固定镜头的 2.5D 表现：背景拆层、脚底坐标、实体碰撞、前后遮挡、方向动画和环境光。先把一个房间做扎实，再扩到城市。
- 参考《潜水员戴夫》《泰拉瑞亚》的即时反馈和系统联动，不承诺同等内容体量，也不添加挖掘/水下玩法。
- 每个阶段交付本地可试玩版本、测试结果和未通过项。自动测试不能替代视觉检查；“脚点未穿入碰撞框”不等于美术轮廓已经准确。
- 保留原有剧情与存档功能，日常分钟循环与旧年度人生事件要明确区分，不能一次做饭就长一岁。

## 顺序与阶段出口

工期为有效开发工作日的粗估，包含测试返工，不是后台运行倒计时；完成第 1 阶段后根据实测重新估算。

| 阶段 | 预计工作量 | 开发内容 | 试玩验收标准 |
| --- | --- | --- | --- |
| 1. 出租屋可玩样板（当前） | 3–5 日 | 移动/绕障、家具轮廓、遮挡、主角比例与步态、休息/学习/做饭/出门、HUD | 从出生点走到全部互动点；连续贴墙、绕桌不穿模；人物不被地板遮掉；键鼠均能完成互动，重复点击只结算一次 |
| 2. 完整的一天 | 5–8 日 | 家→地铁→公司→便利店→家，通勤计时、工作报酬、购买/消耗、睡眠与次日结算、任务指引 | 无调试跳转完成 20–30 分钟流程；每次行动有代价与收益；途中保存重开可继续 |
| 3. NPC 与成长 | 5–8 日 | NPC 行走/交谈、日程、关系反馈、工作技能、首批连续任务 | NPC 可找可聊；关系/技能影响后续选择；任务不重复结算、不形成死路 |
| 4. 扩展地图与内容 | 8–12 日 | 逐场景标定碰撞/遮挡；公园、咖啡馆、医院、旧巷等；扩展事件与经济平衡 | 每张地图通过出生点、出入口、全部热点连通与遮挡检查，再开放给玩家 |
| 5. 完整首版打磨 | 8–12 日 | 动画/音效/反馈、引导、存档兼容、性能、桌面/Web 构建、长流程回归 | 新档/旧档正常；多轮完整流程无阻断错误；有本地发布包、已知问题和恢复办法 |

上述范围约 29–45 个有效工作日（约 6–10 周，含一定返工余量）。完整 3D 重建、大量新职业/剧情、移动小游戏平台适配另行估算，不塞进当前工期。

## 第 2 阶段任务清单

- [x] 每日目标与流程状态：`DailyRoutine` 跟踪通勤/工作/吃饭/休息，跨午夜自动重置，不依赖调试跳转；与旧年度人生事件分离（不推进年龄）。
- [x] 地铁通勤与固定分钟消耗：旅行按目的地消耗 20/35 分钟，抵达公司标记通勤完成。
- [x] 公司工作活动：工位互动，工资+120、健康−6、心情−4、耗时 4 小时，配笔记本道具。
- [x] 需求系统：饱食与精力随真实流经分钟消耗，做饭/睡觉补回，告急时用角色口气提示一次；HUD 四条状态条。
- [x] 便利店购买与背包消耗：货架面板列出全部货品（价钱/效果/描述），买不起的行置灰；买到的进背包，HUD 背包按钮带件数并随处可取用；吃/喝消耗一件、补需求、推进分钟，能顶一顿的计入每日吃饭目标；背包进存档且丢弃目录里已不存在的旧物品。
- [x] 回家睡眠触发次日：20:00 之后或凌晨 5:00 之前上床即睡一整夜，跨过午夜到次日 07:30（白天上床仍只是两小时小睡）；醒来精力回满、健康+12 心情+8，并因整夜时间流过而变饿；昨天一天的每日目标在跨天前先汇成一句小结。存档进 `inventory` 之外新增的 `daily`，读档整体盖回且不会把时间跳变误当成真实流逝去扣需求。
- [ ] 无调试跳转走完 20–30 分钟完整流程的试玩验收。**自动部分已完成**：`tools/verify_day_flow.gd` 全程只用真实交互（点家具标签、走地点按钮、按面板按钮）走完 家→地铁→公司上班→便利店买吃的→回家做饭→睡到次日，钱账与每日目标逐项断言（唯一取巧是把时钟快进到夜里，现实中要等 6 分钟）。**剩余需人工**：20–30 分钟的真实节奏与观感只能靠试玩判断，`E:\Desktop\都市浮生-试玩.bat` 双击即可。（收尾做全员回归时顺手修掉了 `verify_home_input` 的偶发红灯：原因是测试在 `Game._process` 算出输入闸门之前就冻结了 processing，产品侧没有问题，详见 HANDOFF。）

## 第 3 阶段任务清单

- [x] NPC 实体化与交谈：按日程在对应地点生成热点、可点击开聊、有台词与语气；统一显示名与地点标签。
- [x] NPC 日程接入热点：只在当前时段、当前地点出现，换天/换时段自动重建（`NPCScheduleSystem` + `LocationManager.set_visible_npcs`）。
- [x] 关系反馈：每人一条好感值（0–100），**每天只有第一次交谈**加 4 分，重复交谈当日不再加分且明确告知；档位 陌生人/认识/熟络/朋友，升档给一次心情回补与一句叙述；档位显示在热点标签、悬停提示与对话标题上；关系与"今天聊过没"随存档走。
- [x] 工作技能成长：五个手艺档（学徒/上手/熟练/骨干/独当一面）决定时薪，上班攒熟练度、攒够涨技能；技能到「熟练」解锁新选项「大堂 · 谈薪」，谈成永久加工资（最多 3 级），成败看技能+人脉，老张熟络会替你说一句话降门槛；判定确定性，不靠随机数。技能与档位显示在 HUD 与工位标签上。
- [x] 首批连续任务：`data/quests.json` 三条串行主线（先站住脚 → 老张的提醒 → 有人等你回家）。**一次只挂一条、无限时、无失败态，条件全是单调量**（计数/技能/钱/好感/天数），所以不形成死路；计数由真实结算点喂（上班/做饭/买东西），只对当前激活任务生效；进度随存档走，奖励只发一次。任务挂在 HUD 目标行后面，不加新行。
- [ ] 人工验收：三条任务在真实试玩里是否顺、文案是否突兀、HUD 那行会不会太长；"上班攒手艺 → 谈薪 → 完成任务"这条路值得走。

## 每次迭代的检查顺序

1. 读取当前差异，只改当前里程碑相关内容，不覆盖用户已有修改。
2. Godot 无头启动与逻辑回归：碰撞、路径、距离、重复点击、时间和数值结算。
3. 渲染检查：脚底、家具边缘、遮挡、HUD、弹窗；失败则修正，不把“能启动”当完成。
4. 本地试玩：按玩家实际输入走完整流程，不只直接调用函数。
5. 更新本表及本地试玩说明；未通过项明确列出，不推送、不擅自发布。

## 已知风险

- 目前是背景拆层的 2.5D 原型，尚非完整立体场景；除出租屋外，多处前景仍用矩形裁切，存在不正确遮挡。
- 碰撞与可达性测试只能验证配置，仍须对照每张美术图校正障碍。
- 旧人生系统有年度推进逻辑，第 2 阶段必须与分钟/每日循环分离，避免经济、年龄和剧情节奏冲突。
- 现有 NPC 美术来源与脚底标定尚未全部统一；不以扩展地图数量代替体验质量。
- 当前不会自动更新 GitHub Pages；用户批准推送前以 D 盘本地版本为准。
