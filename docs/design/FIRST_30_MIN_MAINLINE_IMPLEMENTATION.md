# 1. 四个验收时间窗

0–1 / 1–5 / 5–15 / 15–30 分钟是**体验窗口，不是失败倒计时**。玩家慢一点不失败；熟练玩家可以更快完成。任何时刻只允许一个 L1“现在要做什么”。

| 体验窗 | L1 当前目标 | 玩家为什么做 | 结束反馈 |
| --- | --- | --- | --- |
| 0–1 分钟 | `现在：先做一顿饭，再出门去公司。` | 一次学会移动、家具互动、时间与资源代价 | 我会操作，而且今天有班要上 |
| 1–5 分钟 | `现在：出门，去城南地铁站。` → `现在：坐地铁去云海科技。` | 第一次地图移动有明确生活目的：通勤 | 约 08:55 抵达公司，认得第一条城市路线 |
| 5–15 分钟 | `现在：先找老张问两句。` → `现在：去工位，完成第一班工作。` | 先建立“这里有人能教我怎么活”，再让工作给钱、消耗状态、推动技能 | 老张成为可回访人物；第一笔工钱到账；技能有进展 |
| 15–30 分钟 | `现在：下班去街角便利店，给今晚做准备。` → `现在：回家，把第一天收尾。` → `现在：睡一觉，结束来到城市的第一天。` | 第一次可选加班取舍；工资换成实际生活资源；闭环到睡眠 | 第一日总结 + Day 2 钩子 |

### 固定时间锚点

使用现有系统即可形成自然节奏：

- 新档：07:30；
- 做饭 +30 分钟：约 08:00；
- home → subway +20 分钟：约 08:20；
- subway → office +35 分钟：约 08:55；
- 老张对话：UI 忙碌期间时间暂停；
- 普通工作 +240 分钟：约 12:55；
- 若选择 overtime +120 分钟：约 14:55；
- 其后补给、回家和正常城市时间继续推进，晚上使用现有整夜睡眠进入 Day 2。

不要为 onboarding 新增迟到判定、打卡失败或真实时间倒计时。

# 2. Golden Path：逐节点实施合同

## Phase A — home：先把自己喂饱

出身选择后，首屏不再强制播放“暗线梦 + 全套系统说明”。只显示：

> 你刚在这座城市落脚。今天是你第一次真正去上班。
>
> **现在：先做一顿饭，再出门去公司。**
> 空着肚子去上班，不会让第一天变容易。

玩家走到厨房完成现有 `meal`。这一动作只教学：

1. 点地面 / WASD 可以移动；
2. 场景里的互动点是真正能做事的地方；
3. 行动会消耗时间和钱，也会改变生活状态。

首 30 分钟不教学：人生四阶段、暗线碎片、结局、所有地图、关系终点、谈薪门槛、职业晋升。

### 确定性处理

Golden Path 默认**做饭是首个 onboarding gate**。玩家在首局尚未完成这顿饭时触发房门，只需要一句生活化提示并留在 home，例如：

> 先垫点东西。第一天没必要饿着去。

不需要新系统，只需后续 01 在现有 leave handler 的 onboarding 分支上做窄门槛。

做饭后切换：

> **现在：出门，去城南地铁站。**
> 公司在另一头。先把路认下来。

### 开场顺序

当前 `_choose_origin()` 是“梦 → 出身旁白 → 一组系统说明”。首局应改成：

1. 出身一句话；
2. 当前目标；
3. 一条上下文操作提示。

`DARK_INTRO` 和完整说明资产保留，只是首日不抢首屏。这里不决定未来市场宣传到底偏现实生活还是暗线，只决定 onboarding 的信息顺序。

## Phase B — subway：第一次通勤

### home → subway

> **现在：出门，去城南地铁站。**
> 这是以后每天都要走的路。

### subway → office

到站后目标变成：

> **现在：坐地铁去云海科技。**
> 今天先把第一班工作做完。

阿哲按现有日程可能在地铁出现。他可以作为“城市里已经有人生活”的环境 NPC，允许玩家主动交谈，但：

- 不产生“必须找阿哲”的主目标；
- 不因没聊而阻断通勤；
- 不展示关系终点或暗线目标。

抵达 office 约 08:55 后，目标不是立刻工作，而是：

> **现在：先找老张问两句。**
> 第一天先认个人。以后遇到工作上的事，至少知道问谁。

## Phase C — office：先认人，再上第一班

### C1. 老张第一次出现

老张现有 office 日程 08:00–12:00，08:55 到达时稳定可见。这个顺序避免 12:55–13:00 的自然空窗，不需要重写 `NPCScheduleSystem`。

首局找他的动机不是“好感 +4”，而是：

> **“这个人知道怎么在这里混下去。”**

第一次有效交谈后的认知反馈：

> 老张记住你了。以后工作上的事，可以再来问他。

首局不讲好感 20/45/70，也不提前讲谈薪数学门槛。关系数值仍可后台正常结算。

### C2. 第一班工作

对话结束后目标立刻切到：

> **现在：去工位，完成第一班工作。**
> 先把今天最重要的事做完。

使用现有普通 `work`：4 小时、工资、健康/心情代价、技能熟练度。

工作结束必须同时让玩家看见三件事：

1. **钱变多了**：劳动能解决生存问题；
2. **身体/心情付出了代价**：工作不是纯收益按钮；
3. **技能有进展**：重复工作仍在改变自己。

结算后 L1 不再要求找 NPC，而直接变成：

> **现在：下班去街角便利店，给今晚做准备。**

---

## Phase D — office：第一次真实取舍——要不要加班

`GAME-CONTENT-012` 的 office overtime 候选应在首 30 分钟第一次出现，前提是该生产任务先被 00 接受并集成。

它只能是**次级可选行动**：

> 再加会儿班 · 2小时 · 加班费 +X · 健康−4 · 心情−8 · 每天一次

L1 始终保持：

> **现在：下班去街角便利店，给今晚做准备。**

第一次出现可给一次轻提示：

> 你可以现在下班，也可以再卖两个小时。多一点钱，少一点自己。

Golden Path 默认不强制加班。选择加班后仍回到便利店目标；跳过也走同一个节点。

这是首局最重要的价值教学：

> **没有“最佳按钮”，只有你现在更在乎什么。**

---

## Phase E — store：工资开始变成生活

主线给出地点理由：

> **现在：去街角便利店，买一份今晚能用得上的东西。**
> 工资不是分数。它首先要拿来让你活下去。

使用现有货架/背包系统。泡面、饭团、面包都属于现有廉价、可负担的生活用品；首局只要求**买至少一件食物**，不要求把商品送给任何 NPC。

### 陈姐

陈姐现有 07:00–23:00 稳定在便利店。她是首局第二个“值得记住的人”，但交谈可选，不作为通关条件。

玩家对她的认知应该是：

> **“她知道这附近怎么生活。”**

她的未来价值是吃饭、健康、晚归、街坊消息，不是“再刷一次 +4”。

购买完成后：

> **现在：回家，把第一天收尾。**

---

## Phase F — home：第一晚

回家后不再新开公园、咖啡馆、医院、旧巷或天台的主目标。

> **现在：回家，把第一天收尾。**
> 今天已经够长了。

若尚未到现有整夜睡眠时段，玩家可以自由走动、查看背包、做轻量家中活动，但系统不再生成新的主线目标。到夜间睡眠条件满足后：

> **现在：睡一觉，结束来到城市的第一天。**

使用现有整夜睡眠跨天。

### onboarding 完成条件

导演默认选择：**第一次成功完成整夜睡眠时写入现有 `flags["onboarding_complete"] = true`。**

原因：`day >= 2` 会把“其他行为意外跨午夜”也当成完成 onboarding，而 flag 能准确表达“玩家真的把第一天收尾了”。`flags` 已随 `GameState` 存档，因此不需要新增 save schema。

### 第一天总结

第一晚的反馈不能只是一排勾。至少重新告诉玩家：

- 我认得家→地铁→公司的路；
- 我认识了老张；
- 我完成了第一班工作，钱真的到账；
- 我看见工作会消耗健康/心情，也会推动技能；
- 我知道街角哪里可以买东西；
- 我第一次遇到“多赚一点还是早点走”的选择（若 overtime 已集成并显示）。

Day 2 醒来后的钩子：

> **第二天。昨天你只是撑过去了，今天开始，你得想办法让日子过得像自己的。**

# 3. 地图解锁：首日为什么去、什么时候看见

现有 `VISIT_UNLOCKS` 是 `home→subway→office→park/store→cafe/hospital` 的访问链。首日不能把技术解锁直接等同于玩家应该看见的目的地。

| 地点 | 首 30 分钟 | 第一次去的理由 | 导演要求 |
| --- | --- | --- | --- |
| home | 立即 | 我住在这里 | 开局锚点 |
| subway | Phase B | 去公司通勤 | 吃完饭后成为唯一新目的地 |
| office | Phase B/C | 第一天报到、老张、第一班工作 | 到地铁后出现/突出 |
| store | Phase D/E | 下班买今晚需要的东西 | 第一班结束后成为下一主目的地 |
| park | 不作为首日目的地 | Day 2+ 第一次需要喘气/恢复时 | onboarding 隐藏或不突出 |
| cafe | 不作为首日目的地 | Day 2+ 有见人/休息/兼职的理由时 | side gig 也随此后置 |
| hospital | 不作为首日目的地 | 健康问题/事件给出具体理由时 | 不作为旅游点 |
| alley | 隐藏 | 后续普通生活或暗线有明确理由时 | 首小时不营销暗线 |
| rooftop | 隐藏 | 后续情绪/人生节点 | 首小时不开放为观光点 |

### 最小技术合同

首日只需要一个**导航可见 allowlist / focus**，不必立即重写整个地点解锁系统：

- Phase A：`home`；
- Phase B：`home + subway`，到 subway 后再允许 `office`；
- Phase C/D：`home + subway + office`；
- 第一班结束：加入 `store`；
- `park/cafe/hospital/alley/rooftop` 在 onboarding 完成前不进入旅行按钮竞争层。

现有底层 `unlocked/visited` 可暂时保留用于兼容，但**旅行 UI 必须以 onboarding allowlist 为准**。若实现必须修改 `LocationManager`，00 需要给 01 或 02 一个明确、窄范围的高冲突文件授权；07 不替代代码 owner。

第一晚完成后解除 allowlist，再由 Day 2 的任务/NPC/需求逐步给地图理由。不要因为 `visited` 自动链存在，就把所有技术已解锁地点立即展示成同权按钮。

# 4. NPC：首日出现顺序与再次寻找理由

- **为什么以后再找**：她可以承载附近生活、吃饭、健康和晚归信息。

## 阿哲 — 环境 NPC

- 地铁现有日程可让他首日被看见；
- 首日不派任务、不阻断通勤；
- Day 2+ 再承担“公司之外还有别的生活/工作方式”的对照。

## 小雨

首 30 分钟不承担主线节点。现有 roommate / close friend / romance possibility / housing canon 仍未决，因此 07 不新增“她等你回家”“给室友带东西”等首日事实。

## 老周 / 疯道士

首日不引导寻找。公园与暗线都不是第一天问题。

# 7. HUD / Tutorial 精确层级

首 30 分钟只允许四层信息。

## L1 — 唯一当前目标（最高视觉权重）

固定格式：

> **现在：{动词 + 地点/对象}**
> {一句为什么}

按顺序只有以下 8 条之一：

1. `现在：先做一顿饭，再出门去公司。`
2. `现在：出门，去城南地铁站。`
3. `现在：坐地铁去云海科技。`
4. `现在：先找老张问两句。`
5. `现在：去工位，完成第一班工作。`
6. `现在：下班去街角便利店，给今晚做准备。`
7. `现在：回家，把第一天收尾。`
8. `现在：睡一觉，结束来到城市的第一天。`

任何时刻只显示一个。

## L2 — 生存/资源状态

保持现有：钱、健康、心情、饱食、精力、时间、天气。它们是仪表，不是七条并列任务。

## L3 — 今日完成度（弱信息）

可以保留 `DailyRoutine`：

> 今日：通勤 / 工作 / 吃饭 / 休息

但它只作为回顾，不用 `next_task_label()` 抢 L1；也不因为某个勾未完成就产生第二个同权主目标。

## L4 — onboarding 期间隐藏

- `立足 / 成家 / 立业 / 归途`；
- 10 万/50 万/200 万和 60 岁目标；
- 暗线碎片、追查状态、暗线结局标签；
- q1–q3 当前步骤与完成 toast；
- 谈薪数值门槛；
- 好感 20/45/70 的终点式提示。

### Tutorial 规则

不要再一次性弹五条系统说明。操作教学跟随当前动作：

- 首次 home：`点击地面或用 WASD 移动。`
- 靠近厨房：`点击标签或按 E 互动。`
- 第一次打开旅行：`只去当前生活真正需要去的地方。`
- 第一次购买：`买到的东西会进背包，饿的时候可以用。`

每条提示只解决眼前操作，不解释未来几十年。

# 8. q1–q3：首日如何避免目标冲突

当前 q1 是：`work_shift → skill>=55 → meal_cooked → money>=3000`。四出身技能/钱差异很大，且 q1 closing 是“这个月”的语义，因此它不适合承担 Day 1 onboarding。

首日实施合同：

1. `onboarding_complete == false` 时，q1–q3 **不进入 HUD L1/L4，不弹 intro/step/quest toast，不发任务奖励**；
2. onboarding 期间的做饭/工作不用于推动 q1 的计数；
3. 第一次整夜睡眠写入 `onboarding_complete = true` 后，从 Day 2 开始正常挂起 q1；
4. 不改 `quests.json`，不新建 Quest 2.0。

这比“只隐藏 UI 但后台照常 evaluate”安全：否则高技能/高资金出身可能在第一天连跳 q1，甚至把 q2 谈薪线提前挤进 onboarding。

# 9. 每 5–10 分钟反馈节奏

| 时间窗 | 可见反馈 | 情绪作用 |
| --- | --- | --- |
| 0–5 | 做饭完成 + 第一目的地出现 | 我会操作，也知道去哪 |
| 5–10 | 老张第一次认知 + 第一班开始 | 这里有人，也有工作要做 |
| 10–15 | 工资到账 + 状态代价 + 技能进展 | 工作真的改变我 |
| 15–20 | overtime 可选取舍（若已集成） | 没有无代价的最好答案 |
| 20–25 | 工资换成实际食物 + 陈姐可选认知 | 钱是生活，不是分数 |
| 25–30 | 回家 / 第一晚总结 / Day 2 钩子 | 我真的过完了一天 |

首 30 分钟不能连续 10 分钟只有数值变化而没有人物、世界或目标状态的确认。

# 12. 00 审核后的最小决策

本方案已经固定 Golden Path，不再把关键体验问题留成开放讨论。00 只需审核是否接受以下实现合同，然后拆任务：

1. 首日主线固定为 `home meal → subway → office → Old Zhang → work → optional overtime → store → home → sleep`；
2. onboarding 完成以第一次整夜睡眠写入现有 `onboarding_complete` flag 为准；
3. Pack A / legacy annual events / encounters 首 30 全部 suppressed；
4. 技术地点解锁可保留，但旅行 UI 在 onboarding 期间使用 Phase allowlist；
5. overtime 首日可选，cafe side gig Day 2+ 且必须先有咖啡馆生活理由；
6. q1–q3 从 Day 2 才开始前台/计数推进；
7. 普通城市 Pack A 在分钟/首月前台启用前，必须先解决“普通 EventSystem 关闭即 `_year_pass()`”的时间语义冲突。

实现目标不是让第一天看起来“内容很多”，而是让玩家在 30 分钟内形成一个清楚的记忆：

> **我吃过一顿饭，认得一条上班路，认识一个同事，挣到第一笔钱，第一次决定要不要继续卖时间，然后买了今晚需要的东西，最后回到自己的住处睡了一觉。**

这才是《都市浮生》从系统演示转成生活模拟的第一块可玩主线。
